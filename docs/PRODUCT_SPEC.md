# CareerCanvas — Master Development Prompt

**Project:** CareerCanvas — Resume & Cover Letter Builder  
**Audience:** Codex / Claude coding agent  
**Stack:** **HTML5 + CSS3 + vanilla JavaScript (ES modules)**, no React, Next.js, Tailwind, TypeScript or mandatory backend.  
**Delivery:** Fully responsive, installable, offline-capable Progressive Web App (PWA).  
**Business model:** 100% free for end users, no subscription, paywall, usage caps, required accounts or paid services.  
**Design reference:** The user-provided **CareerCanvas redesigned concept image** (the second, darker blue/violet redesign). Ask for/locate that reference in the agent workspace; **do not pretend to see it if unavailable**.

---

## 0. Your mission and working agreement

You are the senior product designer, UX architect, accessibility engineer, front-end developer and QA engineer responsible for shipping CareerCanvas. Build a remarkable, trustworthy, modern resume studio that **helps people present credible evidence of their work**, not a tool that promises to get them hired. The app must feel like a sophisticated premium creative product while offering excellent ATS-conscious resume options.

**Follow the supplied redesigned visual concept closely for product character**, not pixel-for-pixel at the expense of usability: midnight navy and deep-indigo surfaces, violet/cyan gradients used selectively in the *app UI*, sophisticated light surfaces in the document workspace, nuanced shadows, premium responsive typography, subtle luminous highlights, rich interactive controls, polished desktop and mobile layouts. The reference includes a landing page, template gallery, editing studio, live resume preview, mobile views, design customization, cover-letter editing, document management and export. **Treat it as a concept, not as evidence that all depicted features are already implemented.**

### Hard constraints
1. Use only standards-based **HTML, CSS and vanilla JavaScript** for app logic. Browser-native Web APIs are allowed. Small, audited, locally bundled open-source utilities can be considered only if truly necessary and must be justified; no reliance on CDNs at runtime.
2. No server, database service, authentication, account creation, paid AI, analytics trackers, advertisements, third-party collection of resumes or cloud upload. All personal content stays on the device unless a user deliberately downloads/shares a file.
3. The PWA must install on compatible browsers, work offline after initial successful load, and not lose edits during install, refresh or an update. Document genuine iOS/browser limitations.
4. **Do not promise ATS success, interviews or jobs.** Provide plain-text-oriented templates and practical, evidence-based writing guidance.
5. **Never auto-fabricate** dates, employers, qualifications, skills, performance metrics, certifications or achievements. Example content must be clearly labeled sample content and replaced/removed before export if appropriate.
6. No fake PDF-generation claims: primary PDF path is **browser Print → Save as PDF**, driven by deliberate print CSS and print guidance. It is *not* a guaranteed identically rendered PDF file generated by a custom PDF engine. DOCX export is out of scope unless a genuinely reliable implementation is subsequently approved and tested.
7. Make accessibility a release blocker: semantic HTML, keyboard access, visible focus, proper labels, errors, contrast, screen-reader announcements, reduced-motion support and non-drag alternatives to reordering.
8. Do not begin subsequent phases just because they are written below: complete and verify the current phase, report status and commit if the repository and user workflow permit it; then follow the user's instruction to continue. **Never falsely claim testing, commits, deployments or platform verification.**
9. Do not require paid hosting or paid dependencies. A free static hosting target can be used when requested, subject to its real quotas/terms. Do not assume a GitHub repository, deployment credentials or CI already exist.
10. Keep design, architecture and end-user functionality coherent across all phases. No decorative buttons or fake interactions.

## 1. Product vision and positioning

**Tagline:** “Create a resume that makes your work stand out.”  
**Supporting promise:** “Modern, professional resumes and cover letters. Live preview. Private by default. Free forever.”  
**Personas:** students/first-time applicants, career switchers, experienced professionals, technical candidates, and creative professionals.  
**Unique value:** visually excellent and *practically useful* documents, prepared entirely in-browser with no account, using intelligent-but-non-AI writing guidance and an accurate live editor-to-print workflow.

### Product principles
- **Content before decoration:** beautiful design must not obscure achievements or make reading difficult.
- **Confidence and control:** always know what will be exported, when changes were saved and where private data is stored.
- **Fast time to first resume:** from landing to usable resume within minutes.
- **Flexible but guided:** comprehensive options progressively disclosed, no intimidating form walls.
- **No false claims:** no automated job matching, ATS scores or hiring guarantees masquerading as validated results.
- **Accessible by default:** equally good with mouse, keyboard, touch and assistive technologies.

## 2. Visual design system — reference-led redesign

### Aesthetic
**CareerCanvas Studio:** product chrome is dark indigo/navy with selective cyan-to-electric-violet accents; editing areas are mostly crisp white or carefully tinted neutral surfaces; document templates have independent, purposeful identities. High-quality typography, layered depth, strong hierarchy, rich hover/active states and precise spacing. Avoid a generic SaaS template, excessive glowing borders or illegible dark resumes.

### Reference tokens (tune with visual QA)
- Background/ink: `#091226`, `#101B36`, `#182347`
- Main accent: `#536BFF`; secondary violet: `#9747FF`; cyan: `#37C8F7`
- Light workspace: `#F5F7FB`; paper: `#FFFFFF`; muted text: `#64748B`
- Positive: `#12856A`; danger: `#CF3F5C`
- Spacing: 4px base rhythm; generous 16/24/32px group spacing.
- Radii: 10–16px for controls/cards, 18–28px for prominent panels; paper itself must stay visually like paper.
- Use locally packaged fonts or robust system stacks; prefer readable body faces and one expressive but professional heading face. Respect export licensing and offline availability.
- Dark/light interface themes plus auto/system setting, independently from resume template color. The print document must never inherit dark-mode UI chrome accidentally.

### Motion grammar
- Interactive transitions 120–240ms, large panel transitions 250–420ms, consistent easing (e.g. cubic-bezier(0.2,0.8,0.2,1)).
- Template switch: refined crossfade/scale without causing layout jumps or resetting scroll unexpectedly.
- Card tilt/hover depth should be restrained and pointer-capability aware, not a mandatory animation.
- Autosave status subtly changes from “Saving…” to “Saved on this device.”
- Section addition/removal and reorder should animate transforms/opacity where feasible.
- Respect `prefers-reduced-motion`; disable parallax, avoid nonessential animations and make all controls immediately usable.
- Use visual effects in the interface, **not** in print output.

Preview template in a modal/screen; **Use template** changes styling but preserves existing content and order where supported. ### Editor Studio — Desktop
Recommended responsive desktop organization:
1. Collapsible left **Sections** rail: Personal Info, Summary, Experience, Education, Skills, Projects, Certifications, Languages, Links and custom sections; reorder affordances; add-section action.
2. Center **Content Editor**: clearly labeled fields, repeatable entries, safe rich formatting limits, dates, checkbox “Current role,” guidance beside fields, inline validation, reorder and duplicate/delete confirmations.
3. Right **Live Document Preview**: paper proportions, zoom (fit/page/width), pages when content overflows, print-safe representation and direct export controls.
4. Persistent contextual top bar: document title/rename, last-saved state, Undo/Redo, Preview, Design, Save/Export, responsive overflow menu. No misleading cloud sync icon.

At 1024–1280px, collapse rail and allow preview resizing or split-view choice. Do not force tiny forms or tiny unreadable documents.

### Editor Studio — Mobile
A mobile-first workflow with **Edit / Preview / Design** bottom tabs and predictable browser back behavior. Edit uses accordion-style sections; Preview renders the page fitting screen width with optional pinch/zoom alternative and readable text mode; Design uses cards, color swatches and sliders. Export is always discoverable, but don't obscure key form controls with fixed chrome. Preserve editor field focus and scroll position when switching tabs. Test 320, 360, 390, 430, 768, 1024 and 1440px widths, portrait and landscape.

### Saved Documents
Local document dashboard with resume/cover-letter cards, meaningful names, last edited date, template badge, open, duplicate, rename, delete with confirmation, export, and user-initiated JSON backup/restore. Clearly differentiate **saved locally** from backed up; private/incognito and cleared-storage behavior must be explained. No automatic syncing.

### Settings / Privacy
Theme (Light/Dark/System); motion (System/Reduced); default paper size (A4/US Letter); units where relevant; preview zoom; default font size; date formatting where reasonable; autosave status; export & data backup; restore; clear all local content (double confirmation); privacy/offline help; app version and update state; accessibility information; keyboard shortcuts. No account tab, subscription banner or fake cloud sync.

## 4. Template collection — eight meaningful styles

Build eight *genuinely different* templates, not recolors of one document. Names and targets:

1. **Aurora** — visually expressive navy/violet presentation, sophisticated hero block, selective graphic accents; creative portfolios and design roles. Clearly flag as **visually bold / may be less ATS-friendly**, and offer a clean printable alternative.
2. **Summit** — excellent single-column editorial typography, refined clean spacing, minimal visual accents; strong default **ATS-conscious** option.
3. **Velo** — crisp technology resume with restrained blue accents, strong skills and project hierarchy; avoid graphics-as-data, choose sensible column fallback.
4. **Slate** — dark-inspired executive visual identity in on-screen gallery; ensure **ink-efficient print variant** (no full-page dark fills by default), carefully handle contrast.
5. **Bloom** — tasteful nature-inspired, warm and elegant, optional restrained decorative motif; creative/human-centered roles.
6. **Grid** — strict alignment and hierarchy, black/white, clean linear structure; strong **ATS-conscious** option with actual logical reading order.
7. **Vertex** — bold editorial headings and impact-driven layouts; creative/leadership personal brand, with sensible print fallback.
8. **Nexus** — modern modular design, contemporary but restrained, technical and product roles.

**Nonnegotiable:** Decorative template appearance does not mean machine-readable ATS output. Clearly label ATS-conscious templates only as a *design objective*, not a pass guarantee. At least **Summit and Grid** must be single-column, no essential icons, no content in CSS pseudo-elements, standard headings, selectable text and sensible top-to-bottom reading order. Any templates with sidebars, progress charts or photos should offer content-complete single-column print variations or an explicit “Simplified/ATS-conscious PDF style” option. Never add invented success percentages or superficial numerical “experience meters” to a candidate’s resume.

### Template design customization
- Theme accent/palette, font pairing, title scale, body scale, line height, section gap, margins, divider style and header style.
- Controls must affect live preview and print consistently; validate min/max ranges and reset to template defaults.
- Hide or disable incompatible settings with clear explanation; do not allow inaccessible color combinations without warnings.
- Avatar/headshot optional, never mandatory, stored privately, with understandable warning that some fields/regions/employers discourage photos. Exporting includes it only when explicitly enabled.

## 5. Structured content model and writing experience

### Resume data
- `id`, `schemaVersion`, `title`, `createdAt`, `updatedAt`, `templateId`, `pageSize`, `designSettings`, `sectionOrder`, `sections`, `contact`, `links`, `photo` reference (optional) and `metadata`.
- Core **profile/contact**: full name, professional title, email, phone, location (city/region only by default), website, LinkedIn/portfolio and optional additional links.
- Professional summary: plain text / constrained formatting.
- Experience entries: title, organization, location, start/end month/year, current role, achievements bullet array.
- Education entries: program, school, dates, details.
- Skills: grouped phrases (avoid misleading “skill meters” by default).
- Projects: name, role, dates, link, outcomes.
- Certifications: title, issuer, issue date, optional credential link.
- Languages: language and user-asserted proficiency.
- Custom sections: heading plus text or repeated bullet entries; prevent unsafe HTML.
- Support section and entry ordering, toggling visibility and undo/redo actions.

### Writing guidance (non-AI, local, free)
- Prompt users for **action + method + impact**, with optional examples clearly marked as illustrative.
- Explain how to write accomplishment bullets, consistent tense, readable dates, concise summary and role-specific skills.
- Flags: missing contact, inconsistent dates, exceptionally long paragraphs, empty headings, repeated bullets, overlong resume (advice, not hard limits), orphan headings and unsupported external links.
- Never invent percentages (“increased sales 40%”) or claim that a keyword automatically improves an ATS ranking.
- A gentle checklist (“Contact details present”, “Experience uses clear bullet points”, “Preview inspected”) rather than pseudoscientific ATS scores.
- Sample profile uses **explicitly fictional placeholder** data, and must not be silently exported as if it were user-provided.

### Controlled formatting
Prefer plain text and real bullet structures; if formatting is enabled, only allow a small, sanitizable subset (bold, italics, bullet lists and hyperlinks). Never use untrusted `innerHTML` for user text. Sanitize data in both editor rendering and preview, using text nodes or rigorously controlled elements. No `eval`, remote HTML or insecure `javascript:` links.

## 6. Cover letters

**Phase 5, after the resume core is stable.** A dedicated editor with matching template identity and palette, separate from resume drafts. Offer:
- Reuse user-approved contact/header data from a selected resume; never modify that resume silently.
- Fields: recipient (optional), company, role, date, greeting, opening, 1–3 body sections, closing and signature.
- Live preview matching selected resume template, print-to-PDF, clear page-break handling.
- Friendly guidance for personalizing the letter; no claim of AI-generated copy and no fabrication of company facts.
- Local autosave, duplicate/rename/delete, backup/restore.

### State and persistence
- Prefer **IndexedDB** for multiple resumes, cover letters, optional compressed local photos, and schema migrations; use `localStorage` for light non-sensitive settings if useful. Make feature detection and backup warnings explicit.
- Debounced autosave on input, plus flush on `visibilitychange` and page transitions where available; ensure pending changes cannot be silently discarded. Async saves should be serialized to avoid older writes overwriting newer ones.
- Explicit migration strategy and versioning; robust error handling for quota exceeded, unavailable storage, failed transaction and corrupted backups.
- Persist only user-authored data and declared local settings. Do not store secrets or transmit document contents.
- Undo/redo should group rapid typing appropriately; changes should be recoverable during current editing sessions.
- JSON backup: export validated versioned data (with optional embedded photo only when explicitly selected), meaningful filename, sensitive-data warning, local import preview, schema validation, migration and duplicate strategy. Import must never execute scripts.

### Preview and printing
- Build one canonical semantic resume content representation, then present it through template styles. Avoid maintaining divergent “editor,” “preview,” and “print” content models.
- Preview uses a paper canvas with CSS `aspect-ratio` appropriate to A4/US Letter and a deterministic measurement strategy. Avoid pretending viewport scaling guarantees identical pagination.
- Implement print stylesheet with `@media print`, `@page` margins/sizing where supported, hiding every app-only surface, no clipped content, no accidental dark background, readable type and logical heading/page break rules (`break-inside`, `break-after`, etc. where supported).
- Explain OS/browser differences: user must choose Save as PDF in print dialog; Chrome/Edge/Safari/Firefox can differ. Check headings, hyperlinks, selectable text, 1–3+ pages, long bullets, missing images and page breaks.
- Provide a preflight print preview/review checklist and visible print instructions, including turning on/off background graphics if needed. If direct PDF generation is later introduced, scope/test separately rather than claiming equivalence.

### PWA details
- Manifest: app name/short name, icons (192/512 and maskable if appropriate), `display: standalone`, start URL, theme/background colors and sensible scope.
- Register service worker from secure context (`https` or supported localhost); app shell and necessary local assets cached for offline usage.
- Version cache carefully, delete obsolete caches only after successful activation, ensure new UI doesn't run against old incompatible data without migration and never cache user resumes as publicly shareable URLs.
- Handle update waiting state with user choice and no data loss; offer offline/online status indicators that do not imply cloud sync.
- Graceful fallback when service workers/PWA installation unsupported. No fake “Install” button; show only if `beforeinstallprompt` supported, and provide manual instructions on other platforms.

### Testing and security
- Zero unsolicited network calls after installation/offline test; local assets only.
- Security: restrictive CSP appropriate for a static app, no remote scripts or inline event handlers, link protocol validation and rel protections for opened URLs.
- Test HTML injection/XSS with contact, custom headings, bullets and JSON import.
- Accessibility: WCAG 2.2 AA target; logical focus order, 44px-ish touch targets where practical, color contrast, screen reader descriptions, `aria-live` for save/error states, confirmation for destructive actions, keyboard reorder alternatives, reduced motion.
- Avoid shipping demo photographs or fonts without clear asset licensing.

### Phase 4 — Print-to-PDF, local backup/import and reliability

**Milestone: one-day MVP functional core.** If time is limited, prioritize one deeply tested ATS-conscious template and one expressive template before expanding Phase 3; never sacrifice printing correctness or data safety to claim eight templates are complete.

### Phase 5 — Matching cover-letter builder

**Acceptance:** letter can be created offline without a resume; optionally uses contact information with consent; prints without clipped paragraphs; no invented claims; all changes survive reload.

### Phase 6 — Premium interaction and finishing polish

**One-day MVP priority:** app shell, reliable structured resume editor, local autosave, two high-quality templates minimum (one ATS-conscious, one expressive), live preview, print CSS/PDF workflow and working offline PWA.

## 10. Risk register and mitigation

| Risk | Severity | Mitigation |
|---|---|---|
| Fancy templates hurt ATS parsing | High | Flag visual templates; ship single-column options with selectable text and logical order |
| Preview diverges from printed pages | High | Use shared markup/style tokens, print regression suite and browser print instructions |
| Browser storage deleted/quota reached | High | JSON export, failure warnings, storage-health UI, documented privacy limitations |
| Losing edits during rapid navigation | High | Serialize/debounce saves, flush where possible, guard route transitions |
| Complex eight-template scope overruns a day | High | Two-template MVP first, Phase 3 expansion in later work |
| PWA stale cached assets after update | Medium/High | Versioned shell, conscious activation and migration handling |
| Dark ink-heavy resumes waste toner | Medium | Ink-friendly Slate print mode and clear preview labels |
| Accessibility regression from visual effects | High | reduced-motion, keyboard alternatives and contrast/focus audit |
| Browser-dependent print settings | Medium | clear guidance, tested fallbacks; no direct-PDF guarantee |
| Local photos increase storage and privacy sensitivity | Medium | opt-in, compression, storage indicators, photo-free defaults |
