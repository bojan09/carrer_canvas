# Deployment (free static hosting)

Nothing here has been deployed from this repository yet; steps are for you to run.

## Vercel
1. Import the GitHub repository. Framework preset: Other. Build command: none. Output directory: repository root (`.`).
2. `vercel.json` sets: no-cache for `sw.js` and the HTML shell, the manifest content type, a one-week cache for fonts, and security headers (strict CSP with no inline script or style, `frame-ancestors 'none'`, no referrer, camera/microphone/location denied).
3. Hash routing needs no rewrites. Serve over HTTPS (service workers and install require it; Vercel does this).
4. After the first deploy check: `https://<host>/sw.js` returns `no-cache`; DevTools > Application shows the service worker running and the manifest installable; reload offline works after one online visit.

## Releasing a new version
1. Bump `APP_VERSION` in `js/config.js`, `CACHE_VERSION` in `sw.js` and `version` in `package.json` (a unit test enforces equality).
2. Add any new JS, CSS, font or icon file to `PRECACHE` in `sw.js` (a unit test enforces this). Fonts are generated by `node scripts/build-fonts.mjs <dir>`.
3. `npm test` and `npm run e2e` (needs Playwright, Chromium and poppler-utils; axe path via `AXE_PATH`).
4. Push to `master`. Users get a "new version ready" toast; their work is saved before the page reloads.

## Other hosts
Any static host works if it serves `sw.js` with `Cache-Control: no-cache` and sets a CSP equal to or looser than the one in `vercel.json` only where needed.
